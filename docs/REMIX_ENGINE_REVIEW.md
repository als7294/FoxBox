# REMIX engine review (PM workflow, salvaged 2026-09-29)

A multi-agent review of the REMIX engine at `fb8c13b`: a map, four idea lenses and one judge. It was stopped before implementation, when the user's listening feedback redirected the work to genre-authentic sound (see the sound bible). The bugs below were probed on synthetic audio.

## Gaps between the plan and the code

- The plan says GENRE FLIP 're-pitches the bass', and the backend says 'Re-time the bass groove to the new feel'. The code only renders the groove at the style tempo: no re-pitch, no half-time or triplet reshaping, and FLIP_STYLES.half_time is never read.
- The plan's flip styles are 'Half-time trap, riddim, deep dubstep, 140'. The code has halftime, riddim, dubstep140, fourfloor and dnb, so deep dubstep is missing. There's no engine helper that emits FlipStyle[] for GET /api/flip-styles.
- The backend says 'Detect A's drum hits: onsets plus a band split'. drum_hits uses band-passed onsets only, and split_drums (HPSS, about 28 s) is never called by the flow.
- The backend says the draft is 'loudness-matched per lane (pyloudnorm)'. Only groove clips (the engine's own integrated_lufs) and mashup B sections are matched. Kit lanes are not matched to the original drums.
- The backend says 'Crossfade at the phrase line, and duck the bass under the other track's bass'. The code does sequential 0.25-beat fade-out and fade-in on adjacent clips: a dip that also blunts B's drop hit. It avoids a double sub by replacing, not by ducking.
- The backend says 'always phrase-aligned (8/16 bars)'. Sections follow the song structure, and mashup B parts are 4-8 bars (the scan part length), so a B drop replacing A's 16-bar drop shortens the remix to non-16 phrases.
- MashMatch.tempo_ratio 'B's clips are stretched': half- and double-time matches, which scan allows and labels, are rendered as a raw remix.bpm/B.bpm stretch (2x or 0.5x speed), and B's beat offsets ignore the multiplier. tempo_ratio is never read.
- The plan lists 'energy and spectral fit' for MASH RADAR. Only the spectral band-share fit is scored, and SongSection.energy is unused.
- The VIP option 'duplicate the last drop as a VIP drop' matches the doc literally, but the copy is identical (no patch or flip variation).
- The plan says BASS DNA reads 'half-time'. It is carried from the section by the server only: prepare never sets it, and no renderer uses it.
- The backend says 'A finished remix becomes a Song whose structure comes from the arrangement'. No engine helper maps Remix sections to SongStructure (drops_s, builds, phrase_bars); that's left to S3's export.
- The backend performance targets: prepare < 1 s per 8 bars is borderline for flips (about 1 s per 8 bars per lane). Surge < 1 s per 8 bars is unmeasured here (no surgepy). Export < 20 s for 5 minutes is at risk, since mixdown alone is 8-15 s for about 90-100 bars.
- The backend's lean checks call for one golden BUILD per recipe on the local test corpus. The goldens were run by hand in S2's scratchpad. No repo test touches the test song, checks LUFS on target, or checks drops on phrase lines.
- The backend module table names fvwks_fx/remix/run.py; the code is pipeline.py. The contract GrooveWobble.shape still says 'Only sine is told apart', but the code returns square/saw/sine. The BassGroove doc says bend ±12 st, but Surge uses ±24.
- Remix.beats_per_bar and SongAnalysis.beats_per_bar are ignored everywhere in REMIX (4/4 hard-coded); mash is the one exception, using beats_per_bar for part starts.
- At fb8c13b no server code calls fvwks_fx.remix.run or clip_key (S3's routes and jobs aren't on this branch). Only fvwks_fx.api.bass_groove, mash_features and mash_scan are exposed.

## Details

### `groove-bar-late-fix` (drop-impact): Put the synth bass back on the drop's first bar (groove clips are one bar late and bar 1 is silent)
- **Benefit:** Today every VIP or flip groove clip plays the next bar's bassline, one bar behind the drums, and the drop's first bar has no bass at all. The bass hit on the drop downbeat, which is the moment the crowd waits for, is missing. With the fix the new bass lands on the drop's 1 with its first note, in phrase with the drums, and the last bar no longer plays the section after the drop.
- **Approach:** I confirmed this with a probe at fb8c13b. The source bass had held notes stepping one semitone per bar (bar k = midi 30+k). prepare_clip on a groove clip with start_bar=5, bars=3 gave bar 1 silent, bar 2 = midi 37 and bar 3 = midi 38, where it should have given 35, 36, 37. That happens on both foxsynth and the numpy fallback. Root cause, prepare.py:107 in _groove: the cut starts at source bar start_bar-1 (a0 = downbeat + (start_bar-2)*bar), then extract_groove gets SongAnalysis(downbeat_s=bar) plus start_bar=2, so t0 = 2 bars into the cut, which is source bar start_bar+1. That counts the pre-roll bar twice. The fix is one token: downbeat_s=0.0, so the cut's bar 2 is src.start_bar. I probed it: the notes then come back 35, 36, 37 from beat ~0. Second edit, groove.py:100: `if not t0 - 1e-6 <= t < t1: continue` drops the drop-downbeat note whenever the onset refiner puts it a few ms early, and also drops any note held across t0. Replace it with an overlap rule: keep a note when min(end, t1) - max(t, t0) >= MERGE_S. Then clip beat to max(t, t0), clip beats to min(end, t1), and shift the bend offsets by the clipped amount, dropping the negative ones. As a side effect this also closes the 'notes run 38 beats past the groove' limit. No contract or signature change.
- **Files:** engine/fx/src/fvwks_fx/remix/prepare.py, engine/fx/src/fvwks_fx/remix/groove.py, engine/fx/tests/test_remix_prepare.py
- **Risk:** Low. The LUFS match already measures the correct source bars, so after the fix the render and its reference finally cover the same bars. Existing groove tests call extract_groove directly with downbeat 0, and the probe shows notes inside the window unchanged. A note clipped at t0 keeps its settled pitch, so a bend that started before the window loses its early part, which is intended. The hand-run goldens will change audibly, which is the point.
- **Test:** Add test_groove_clip_plays_its_own_bars to test_remix_prepare.py. Source: 12 bars at 120 BPM, downbeat 0.5 s, held sine+2nd-harmonic notes midi 31..42, one per bar. prepare_clip on a groove clip {start_bar:5, bars:3, patch_id:'default'} at remix bpm 120. For each output bar, take the peak FFT bin in 40-90 Hz over the bar's middle 1.4 s, convert it to midi, and assert round(midi) == [35, 36, 37]. Also assert bar-1 RMS > 0.05. Today it fails (bar 1 silent, bars 2-3 at 37/38). Also add one extract_groove assert: a 45 Hz note held from beat 0, read with start_bar=2, yields a note at beat 0.0. Run: cd <checkout>/engine && PYTHONPATH=fx/src:contracts/src:synth/src:voice/src:server/src engine/.venv/bin/python -m pytest -q fx/tests/test_remix_*.py fx/tests/test_mash.py

### `pre-drop-breath` (drop-impact): The breath before the drop: a 1-beat stop, then a hard drop entry
- **Benefit:** Every drop gets the classic bass-music stop. Drums, bass and music cut out for the last beat before the drop while the vocal carries through, so the drop lands out of silence and hits much harder. The mashup's 0.25-beat fade-in on B's drop, which blunts B's first kick today, becomes a few-ms click guard, so the first kick and sub hit at full level.
- **Approach:** This is one post-pass at the end of arrange.build, before the return, with no contract change. Add GAP_BEATS = 1.0 (a knob) and DROP_IN_BEATS = 1/64 (~7 ms at 140). For each section k > 0 with kind 'drop', at D = (start_bar-1)*4, change every clip on a lane whose role isn't 'vocals' and that ends exactly at D (c.at_beat + c.beats == D, and c.beats > GAP_BEATS). Set beats -= GAP_BEATS and fade_out_beats = DROP_IN_BEATS. For every clip starting at D, set fade_in_beats = min(fade_in_beats, DROP_IN_BEATS). The gap is real silence everywhere, because clips simply end early: prepare renders clip.beats, mixdown places it, Tone.js schedules it and the .als writes it the same way. The VIP copy (drop→drop) gets the gap too, as a re-entry. song_structure merges runs of the same kind, so no other drop→drop boundary exists in real songs.
- **Files:** engine/fx/src/fvwks_fx/remix/arrange.py, engine/fx/tests/test_remix_arrange.py
- **Risk:** Low. A source whose build runs a snare roll right up to the drop loses its last beat of roll, which is how producers do it anyway. The existing mashup assertion `b_drums.fade_in_beats == 0.25` must become DROP_IN_BEATS. A hard clip start on a sustained pad in B's 'other' stem is covered by the 7 ms fade and masked by the drop's kick. Clip beats change, so clip_key re-renders those clips once.
- **Test:** Add test_drops_get_a_breath to test_remix_arrange.py. On the LAYOUT song with vip + vip_drop=True, for every drop section at beat D (index > 0): every non-vocal clip ending before it ends at D - 1 with fade_out 1/64, the vocal clip still ends at D, and the drop's clips start at D with fade_in <= 1/64. In the existing mashup test, update the fade_in assert to 1/64. One pipeline-level check in test_run_stages (flip): the mixdown RMS over the last beat before bar 9 is < 0.1 x the RMS of the beat after. Run the suite command.

### `riser-impact-fx` (drop-impact): Synthesised riser, drop impact and downlifter on an FX lane
- **Benefit:** The remix gets the transition FX every bass-music drop uses. A 4-bar white-noise riser climbs into the drop, a crash-plus-sub-boom impact lands on the drop's first beat, and a 2-bar downlifter falls out of the drop into the breakdown. All of it sits on its own lane, so the DJ can turn it up, down or mute it.
- **Approach:** No contract change: the clips are KitClipSrc(kit_id='foxbox', pattern_id='fx.riser' | 'fx.impact' | 'fx.down'), since pattern_id is a free library-sound id, on a new lane RemixLane(id='kit-fx', role='kit', slot=None). arrange.build post-pass: for each drop at beat D with a previous section P, add a riser at D - 4*min(4, P.bars) that ends at D - GAP_BEATS if pre-drop-breath has landed, else at D. Add an impact at D, 4 beats long, and an fx.down at the start of the section after a drop when that section isn't a drop, 8 beats long. prepare.py: in _kit, before _synth_hits, `if (clip.src.pattern_id or '').startswith('fx.'): return _fit(fx(clip.src.pattern_id, clip.beats, remix.bpm, sr), n)`. Add fx(name, beats, bpm, sr) of about 20 lines of numpy/scipy, the same STFT pattern split_drums uses. Riser: stft of seeded white noise (2048/512), times a Gaussian-in-log2 band mask 0.6 octave wide whose centre sweeps 200 Hz to 8 kHz exponentially over the clip, times a u^2 swell, then istft and normalise to peak 0.3. Use two seeds for L/R width. fx.down is the riser reversed, y[:, ::-1]. Impact: a sine boom, f = 40 + 60*exp(-t/0.06) with a 0.35 s decay (mono), plus crash noise high-passed twice with np.diff (the foxbox_kit hats trick) and a 0.9 s decay, at peak 0.35. clip_key already hashes src, beats and bpm, so the renders cache for free.
- **Files:** engine/fx/src/fvwks_fx/remix/arrange.py, engine/fx/src/fvwks_fx/remix/prepare.py, engine/fx/tests/test_remix_prepare.py, engine/fx/tests/test_remix_arrange.py
- **Risk:** S4's UI and S3's .als writer see one more lane with role 'kit' and hitless clips. It needs a one-line heads-up to them, and it renders as an empty kit clip until they label it. The FX levels are a guess (peak -10 dBFS before the master), which lane gain can fix. Adding a riser on top of a source that has its own build riser doubles it, and the lane mute covers that. The impact's sub boom adds to the first kick, but the master's mono below 120 Hz and its limiter absorb it, and the boom stays short to limit limiter pumping.
- **Test:** test_remix_prepare.py, test_fx_sweeps_and_impact: fx('fx.riser', 16, 140, SR) has shape (2, n). Last-beat RMS >= 4x first-beat RMS, and last-beat spectral centroid >= 4x first-beat centroid. fx('fx.down') equals the riser reversed. For fx('fx.impact'), argmax|y| < 20 ms, and more than 10% of the energy in the first 0.3 s is below 100 Hz. test_remix_arrange.py: a vip build on LAYOUT has lane 'kit-fx' with a riser ending at each drop's beat (minus GAP_BEATS if present), an impact at each drop's at_beat, and a down at each post-drop breakdown/outro. The existing flip test's 'kit-x' clip count is unaffected. Run the suite command.

### `sidechain-pump` (drop-impact): Sidechain pump: the drop's synth bass ducks under every kick
- **Benefit:** The new bass breathes with the kick instead of smearing over it. You get the pumping, punchy drop that dubstep, riddim and trap producers get from sidechain compression, and the kick's thump comes through clearly on a club system instead of fighting the sub. In a flip it pumps to the new style's kick pattern, not the original's.
- **Approach:** This is baked into the groove clip, so the app's Tone.js playback, the .als and the mixdown all hear it. prepare.py: add kicks_under(clip, remix) -> list[float] | None. It returns the kick beats, relative to the clip start, of the 'kit-x' kit clips overlapping the groove clip (a flip). To expand pattern-only kit clips it reuses the pattern expansion from _kit's first lines, factored into _kit_hits(clip). It returns None when there's no kit lane. In _groove, before the LUFS match, set kicks = kicks_under(...). When that's None and the source has a 'drums' stem, run flip.drum_hits on the source drums cut over [src.start_bar, +bars) with SongAnalysis(bpm=s.bpm, downbeat_s=0.0) and keep kind=='kick' with 0 <= beat < clip.beats (0.09 s measured for 18 bars). Then y *= _pump(n, kicks, remix.bpm, sr). _pump is about 8 lines: a dB envelope that, for each kick, ramps 0 to -PUMP_DB over 3 ms of look-ahead, then recovers linearly in dB (an exponential in amplitude, like a compressor) over PUMP_RELEASE_BEATS = 0.4, combined with np.minimum. PUMP_DB = 8, as calibration knobs. Because the pump runs before the LUFS match, the ducked groove matches the original bass, which was itself sidechained. pipeline.clip_key: `if clip.src.kind == 'groove': body['kicks'] = kicks_under(clip, remix)`, so a style or swing change re-renders the bass. The position-invariance test is unaffected, because it moves a kit clip.
- **Files:** engine/fx/src/fvwks_fx/remix/prepare.py, engine/fx/src/fvwks_fx/remix/pipeline.py, engine/fx/tests/test_remix_prepare.py
- **Risk:** The groove's level curve already carries the original's (smeared) pump. In a VIP the two stack, which is deeper but aligned. In a flip the old pump sits at the old kick positions, a known ceiling that should be marked with a ponytail comment. Trap 808 patches may want a lighter duck, since the 808 often hits with the kick: that's one knob, and a per-category depth can come later. A kick-free bar in the kit means no duck, which is correct. Groove clip_keys change once, so there's a one-time re-render.
- **Test:** test_remix_prepare.py, test_groove_pumps_under_the_kick. Source A: bass = _tracks()[0] (held subs), drums = foxbox_kit kicks every 2 beats at the source bpm. prepare_clip on a VIP groove clip (no kit lane, patch 'default'). Averaged over the kicks, RMS in [kick+5 ms, kick+40 ms] is >= 5 dB below RMS in [kick-120 ms, kick-20 ms]. For a flip remix with a 'kit-x' clip whose hits hold kicks at beats 0 and 2.75, the dip sits at 2.75 beats (±10 ms). clip_key of that groove clip changes when the kit clip's kick moves, and not when a hat moves. Run the suite command.

### `mashup-phrase-parts` (arrangement): Mashup: B's part fills A's whole phrase, and a borrowed build ends right into the drop
- **Benefit:** A borrowed drop now plays for 16 bars, including its switch-up, instead of 8 bars and a jump. The remix keeps its 8/16-bar phrases. A's vocals over B's drop no longer skip 8 bars when A comes back. A borrowed build now plays its last bars, the riser and snare roll, straight into A's drop instead of its quiet first half. B's vocals end where B's vocal phrase ends.
- **Approach:** In arrange.build, in the mashup branch after `at` is found, compute b_left, the bars left in B's own section from match.start_bar. Reuse _sections: b_left = next((t.from_start_bar + t.bars - match.start_bar for t in _sections(songs['B'], 'B') if t.from_start_bar <= match.start_bar < t.from_start_bar + t.bars), match.bars). Then bars = s.bars if b_left >= s.bars else max(match.bars, b_left // 4 * 4). For part=build, from_start_bar = match.start_bar + max(0, b_left - bars), so B's build ends at its own end. Later sections shift by bars - s.bars. For part=vocals, build the B vocals clip on s.model_copy(update={'bars': min(s.bars, b_left)}). MashMatch.bars stays the scored window, with no contract change. Probe at fb8c13b: a part=drop match with bars=8 (mash's PART_BEATS cap, so every real match) gives an 8-bar B drop in place of A's 16-bar drop. A's vocals over it cover bars 17-24, then the breakdown resumes at A's bar 33. With the prototype (scratchpad/arr_proto) it is 16 bars and contiguous. A 16-bar B build now plays its bars 17-24 instead of 9-16.
- **Files:** engine/fx/src/fvwks_fx/remix/arrange.py, engine/fx/tests/test_remix_arrange.py
- **Risk:** b_left is counted on B's own grid, so a half- or double-time match (tempo_ratio m=2) is miscounted. ### `grid-true-sections` (arrangement): Section lengths come from the bar grid, so a pickup can't push every drop off the phrase
- **Benefit:** Tracks with a pickup or a quiet lead-in (downbeat more than half a bar in) no longer get a 9-bar intro. Before, that repeated a source bar and moved every later drop one bar off the 8/16 grid that CDJs and Rekordbox phrase-count, including in the .als export.
- **Approach:** One line in arrange._sections. For every section but the last, bars = next.start_bar - s.start_bar (zip(secs, secs[1:] + [None])). The last keeps max(1, round((s.end_s - s.start_s) / bar_s)). Root cause: structure.py joins the pre-roll before bar 1 into the first section (start_s=0.0), and _sections rounds seconds. ### `flip-kick-sidechain` (mix-master): Duck the flip's bass under the new kicks
- **Benefit:** In a GENRE FLIP the synth groove replays the source bass's bounce (its level curve), and that bounce pumped around the original kick positions. reprogram moves the kicks to the style's pattern. So the new kit kick and the synth sub now hit together on the same beats, two low-end owners at once: the kick loses punch and the sub gets muddy. The bass also dips where no kick lands anymore. A kick-keyed sidechain brings back the bass-music pump on the new pattern, so the kick cuts through and the sub rides between the hits.
- **Approach:** prepare.py: (1) Factor the hit expansion out of _kit into `kit_hits(clip)`: the inline hits, else the FLIP_STYLES pattern repeated bar by bar. _kit uses it. (2) Add `kicks_under(clip, remix)`: a sorted list of (beat from the clip start, vel) for every kick on a kit lane that falls inside [clip.at_beat, clip.at_beat + clip.beats). (3) In _groove, after the LUFS match: when there are kicks, build an impulse of height vel at each kick sample, run it through an exponential release (lfilter, tau 70 ms), then a 2 ms attack (dsp.one_pole_lowpass). Then y *= 1 - 0.5 * min(1, env), a -6 dB duck (`# ponytail: fixed depth and release, per-style if asked`). pipeline.clip_key: when a clip's src.kind is groove, add kicks_under(clip, remix) to the hashed body, so a swing or pattern change re-renders the groove and the app hears the same thing as the export. This does nothing for VIP and mashup, which have no kit lane. The duck lives in prepare, not in mixdown, so app playback and the export match.
- **Files:** engine/fx/src/fvwks_fx/remix/prepare.py, engine/fx/src/fvwks_fx/remix/pipeline.py, engine/fx/tests/test_remix_prepare.py
- **Risk:** The depth (-6 dB) and release (70 ms) are fixed. A muted kit lane still ducks the bass, since mute doesn't re-render clips. The old bounce curve isn't removed, so a leftover dip from it can stack with the new duck. Groove clips re-render whenever kit hits change (about 0.1-1 s each).
