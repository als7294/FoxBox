# S1 VOICE: contract proposals

> **Status: P1–P4 were accepted in `v0.1-contracts` and are implemented on `session/s1-voice`** (words with a
> per-word `throw`, `SourceInfo.bpm`, `SourceInfo.warnings` plus `preview_script`, and the acronyms in `DEFAULT_LEXICON`).

Every item is backward compatible (new optional fields, defaults unchanged) and already has a local workaround,
so nothing blocks on it. P1 is the one that changes how the drops sound. P2 and P3 are small.

## P1. Word timings on Segment, so throws hit the word and not the whole chunk (recommended)

**Problem.** `SegmentFlags.throw` is per chunk. In `EXPECT *US*` the whole segment "expect us" is flagged, so
S2 can only throw the entire chunk, or guess that the throw word sits at the end. `*WE* ARE LEGION` can't be
expressed at all.

**What S1 already has.** Kokoro's duration predictor gives exact word timings (12.5 ms grid, same alignment
the audio was generated from). `fvwks_voice.api.render()` returns them today (`ChunkRender.words`,
`ChunkRender.throw_spans`). For `EXPECT *US*` (am_fenrir) the throw span starts exactly at "us" (1.725 s)
and runs to the chunk end.

**Proposal.**
```python
class Word(Model):
    text: str              # as spoken ("Fawkes" for FVWKS)
    start_s: float         # absolute Source time
    end_s: float
    throw: bool = False    # inside *...*

class Segment(Model):
    ...
    words: list[Word] = Field(default_factory=list, description="TTS sources only; empty for recordings.")
```
- S2 takes throw ranges from the words with `throw=True`. If the list is empty, it throws the whole segment,
  as it does today.
- S4 can highlight the word being spoken in SignalView, and draw word ticks inside segment regions.
- An alternative with fewer fields is `SegmentFlags.throw_start_s / throw_end_s: float | None`. It covers S2
  but not S4.

**Workaround until then.** One segment per chunk, with `throw` on the chunk, exactly as in v0.

## P2. `SourceInfo.bpm`, so STACK voices get the same pause lengths

**Problem.** `[2b]` pauses are sized with `TTSRequest.bpm` (default 120), but the Source doesn't record it. The
server stub re-synthesizes STACK voices with `TTSRequest(script, voice_id, speed)` and no bpm, so at 140 BPM
the main voice's `[2b]` gap is 0.857 s and the stack voice's is 1.0 s. Segment counts still match, and S2
aligns per segment, so this isn't a correctness bug, just a needless mismatch.

**Proposal.** `SourceInfo.bpm: float | None = None` (the bpm used for beat pauses, TTS only).

**Workaround until then.** S3 keeps the request bpm next to the source and passes it for stack synthesis.

## P3. `SourceInfo.warnings`, so the parser can explain itself

The parser is lenient: it drops an unmatched `*`, an unknown `[tag]` and a pause before the first word, and
reports each one as a warning. There is nowhere to return them. The proposal is
`SourceInfo.warnings: list[str] = []`.

**Workaround until then.** `fvwks_voice.api.preview_script(script, lexicon)` returns
`{segments: [{text, say, flags}], warnings}`, the same shape as `fixtures/markup_cases.json`, without
synthesizing. S3 could expose it (for example `POST /api/script/preview`) for the ScriptEditor.

## P4. Built-in acronyms in DEFAULT_LEXICON (small)

ALL-CAPS words are lower-cased so "EXPECT US" isn't read as "U.S.". A few words must stay spelled out, so S1
keeps a built-in guard list under every lexicon: DJ, MC, BPM, CDJ, VIP, EDM, UK, USA, FBI, CIA, NSA, TV.
A user entry for the same word wins. The list would be more transparent in `DEFAULT_LEXICON` as
`{word: "DJ", say: "DJ", acronym: true}` rows, so the LexiconEditor shows them and they can be deleted. S1
would then drop its hidden list.

## Notes on the frozen semantics (no change requested)
- `LexiconEntry.say` wrapped in slashes (`"/fˈɔks/"`) is taken as misaki phonemes. With `acronym: true`, `say` is
  kept in capitals and spelled out.
- A supplied `Lexicon` is taken as the user's complete list: deleting FVWKS in the UI really deletes it. Only
  `lexicon=None` falls back to `DEFAULT_LEXICON`.
- `markup_cases.json` "say" is lexicon plus lower-casing only. Before TTS, S1 also capitalizes the first letter
  and closes the chunk with a period when it has no end punctuation. This matters: without the period, Kokoro
  often clips the last word. For example, "forgive" in "we do not forgive" lasts 0.375 s and stops at
  −41 to −51 dB below peak for am_michael and am_fenrir; with the period it lasts 0.78–0.93 s and decays
  cleanly. The v0 `fixtures/sources/remember__*` were rendered without the period, so their last words may be
  clipped. Regenerating them through `fvwks_voice.api.synthesize` would fix that; the segment structure and
  `script_hash` are unchanged (S1's test checks this).

# Round 2 (after v0.1): recorded-voice upgrades approved by the user (denoise, word timings)

All the engine work is done on `session/s1-voice`. Each item below only exposes it; each has a workaround.

## P5. A denoise control at upload
S1's `ingest(data, filename, kind, *, denoise=None)` runs DeepFilterNet3 (model `deepfilternet3`, MIT, 8.7 MB,
required). Strength runs from 0 (off) to 1 (fully cleaned). With None, recordings and imports get 1.0 and TTS gets 0.

**Proposal.**
- The `POST /api/sources/upload` form gets a `denoise: float | None` field.
- `SourceInfo` gets `denoise: float | None`, the strength applied.
- The IMPORT and RECORD tabs could offer "Clean up: off / light (0.5) / full".

**Why a control matters.** Full strength is right for normal home takes. In very heavy broadband noise it also
costs consonants: at 5 dB SNR about 26–42% of the 4–10 kHz energy is kept. It can't separate a competing voice.

**Workaround:** the defaults above.

## P6. Recordings get a transcript and word timings in the background
`transcribe(source) -> Source` (new hook). Whisper large-v3-turbo writes the transcript, and Qwen3-ForcedAligner
places each word; the model is `whisper-aligner`, opt-in, 2.9 GB, MIT plus Apache-2.0. The result has:
- `info.script` set to the transcript;
- `Segment.words` filled on the segments ingest found, with the last word of each segment keeping its release,
  as for TTS;
- `Segment.text` set to the segment's words.

It takes about 1.5 s for a 5 s take, so the server should run it as a background job after an upload, like
WORLD analysis, and replace the stored Source info, keeping id and audio_id. Throws on recordings then work
word-exactly.

**Proposal.** `SourceInfo.transcript_state: Literal["none", "queued", "running", "done", "error"] = "none"`, so the
UI can show "transcribing…".

**Workaround:** no field; the words just appear in the Source once the job finishes.

## P7. An editable transcript for recordings
`realign(source, script) -> Source` (new hook). The user's corrected transcript, markup included, re-segments a
recording exactly like TTS:
- one segment per chunk, with its `beat_break`, `throw` and `pause_after_*` flags;
- words aligned to the audio, with `throw` on the `*words*`;
- `info.script` set to the script.

The audio isn't touched, so pauses in the markup act as ARRANGE flags.

**Proposal.** `PUT /api/sources/{id}/transcript` with body `{script: str}`, returning `SourceInfo`.
- Errors:

  | Status | Code | When |
  |---|---|---|
  | 400 | `invalid_request` | the source is TTS |
  | 400 | `script_empty` | the transcript has no words |
  | 422 | `align_failed` | the words and the audio couldn't be matched |
  | 503 | `model_not_installed` | the whisper-aligner model is missing |

- In the UI, the ScriptEditor's SAYS line shows the recording's transcript and lets the user edit and mark it.

**Workaround:** without the route, recordings keep the automatic transcript and the silence-split segments.
