# S4 (APP) contract proposals

All items have a working local workaround in `app/`, so none of them block anyone. Ranked by value.

## 1. Persona candidates have no way to be auditioned (needed for VOICES → Persona designer)
- **Problem:** `POST /api/personas/design` returns a `Job` whose `result_ids` are candidate ids. `PersonaCandidate`
  (`{id, audio_id, description}`) exists in the models, but no route returns one, so the UI can't get the
  candidates' `audio_id`s to play them.
- **Proposal (additive):** `GET /api/personas/candidates/{candidate_id}` → `PersonaCandidate`.
  An alternative is to add `candidates: list[PersonaCandidate]` to `Job`, but that is less general.
- **Workaround now:** the UI plays `GET /api/audio/{candidate_id}`, which works if S1/S3 reuse the candidate id as its
  audio id, and shows "audition unavailable" otherwise.

## 2. `--export-dir` should only be a default
- **Context:** Electron passes `--export-dir` on every launch: `~/Music/GUY FVWKS/VoiceBox` when packaged,
  `<worktree>/.devdata/exports` in development (or `FVWKS_EXPORT_DIR`).
- **Proposal (behavioural, no schema change):** a persisted `Settings.export_dir` wins over the flag. The flag only
  seeds a fresh settings store, so the user's folder choice in SETTINGS survives restarts.
- **Workaround now:** none needed in the app. Main reads the export root from `Health.export_dir` and from every
  `export_dir` in proxied responses.

## 3. `Take.source_id` (nice to have)
- "Open in Studio" currently needs `GET /api/renders/{render_id}` and then `GET /api/sources/{source_id}`. Adding
  `source_id` to `Take` would save one round trip. It is additive.

## 4. `Voice.sample_audio_id` (data, not schema)
- The stub returns `null`. The 2 s audition then synthesizes "We are Guy Fawkes. Expect us." per voice through
  `POST /api/sources/tts` and caches it for the session. If S1 pre-renders a sample per voice, auditions become
  instant with no UI change.
